# MyTravelDex 프롬프트 이력 기록

이 스킬은 MyTravelDex 프로젝트에서만 사용한다. 스킬이 적용된 요청을 처리한 뒤, 사용자의 프롬프트 원문과 답변·결과 요약, 변경 파일을 `docs/prompts.md`에 남긴다.

## 작업 규칙

1. 작업 시작 전에 현재 시각을 확인하고 `git status --short`로 기존 변경사항을 확인한다.
2. 사용자의 프롬프트는 수정·요약·의역하지 않고 원문 그대로 기록한다. 단, 비밀값·토큰·OAuth secret·API key 값·개인정보가 포함되면 해당 민감정보는 기록하지 않는다.
3. 답변 또는 작업 결과도 사실에 근거해 한 줄로 요약한다. 완료하지 못한 항목은 완료했다고 쓰지 않는다.
4. 작업 후 `git status --short`를 다시 확인해 이번 작업으로 변경된 파일만 식별한다. 기존 변경사항과 섞이지 않도록 주의한다.
5. 짧은 프롬프트는 `docs/prompts.md`에 다음 표 형식으로 추가한다.

```text
| YYYY-MM-DD HH:mm KST | 프롬프트 원문 | 답변·결과 요약 | 변경 파일: `path/to/file` 또는 없음 |
```

프롬프트가 길어 표 가독성이 나빠지면 표를 사용하지 않고 날짜별 블록으로 기록한다. 이 경우에도 프롬프트 원문은 축약하지 않는다.

6. 작업 결과에 문서 변경이 포함되면 기록 파일도 같은 작업의 변경 목록에 포함한다.
7. 비밀값, 토큰, OAuth secret, API key 값, 개인정보는 이력에 기록하지 않는다. 환경변수 이름이나 서비스 이름만 기록한다.
8. 사용자가 커밋을 요청하지 않았다면 커밋·푸시는 수행하지 않는다.

## 기록 기준

- 이 스킬이 명시적으로 호출되었거나 작업에 적용되었을 때만 기록한다.
- 스킬이 적용되지 않은 과거 대화는 소급해 임의로 기록하지 않는다. 현재 저장소의 Git 이력이나 명시적으로 제공된 대화 요약으로 확인 가능한 작업만 기록한다.
- 변경 파일이 없으면 `없음`으로 기록한다.
- 날짜와 시간은 `Asia/Seoul` 기준 `YYYY-MM-DD HH:mm`으로 기록한다.

## 검증

- `docs/prompts.md`의 표 또는 날짜별 블록 형식이 깨지지 않았는지 확인한다.
- 기록 후 `git diff --check`를 실행한다.
- 사용자 요청 범위 밖의 파일을 기록하거나 수정하지 않는다.
