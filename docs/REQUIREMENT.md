# MyTravelDex 요구사항 명세서

## 밝은 파스텔 UI 개편 (2026-11-07)

기존 기능 계약을 유지하는 디자인 개편이다. 원본 팔레트/스토리보드는 보존하고 theme 의미 토큰으로 하늘 #EFFAFF·민트 #E9F8F1·기존 코랄을 확장한다. 홈 발자국 배지만 제거하고 My 스탬프는 유지한다. 네 지도 범위는 선택기 하나로 통합하고 로그인/계정은 My로 접근한다. 지역명은 상자/체크 없는 회색 글자로 줌 5~9에서 11~15로 변화하며 충돌과 글꼴 확대를 고려한다. 기존 17개 실제 경계 아래 얕은 그림자·구분 레이어를 추가하되 좌표/경계와 선택 강조는 보존한다.

지도 기록은 최대 화면 높이 60%의 하단 사진 패널로 열고 대표사진 우선 가로 갤러리, 작은 제목/날짜, 기존 content의 두 줄 한줄평을 보여준다. 상세에서 전체 내용과 같은 갤러리를 제공한다. 사진 순서/대표 지정/삭제/권한/서명 URL 재발급은 유지하고 관리 동작을 접어 정리한다. 사진 아래 이름은 숨기고 공개 동의된 기존 프로필 사진 또는 로컬 여행 캐릭터 SVG만 표시한다. 접근성 작성자 이름과 친구/My의 이름은 유지한다. 전체 화면과 시작 스플래시·로그인 진입은 밝은 테마로 통일한다.

반응형은 320~1280 폭·가로·fontScale 1/1.5/2, 안전 영역/키보드에 대응하며 최소 48dp 터치·일반 텍스트 대비 4.5:1을 유지한다. 사용자 반응에만 짧은 효과를 쓰고 동작 줄이기를 존중한다. API/DB/RLS/migration 변경 없이 기존 조회·사진 압축·Storage·OAuth·EXIF·초안·소유자 권한을 사용한다. 참고: [Polarsteps](https://www.polarsteps.com/), [Mapicus](https://www.mapicus.app/), [MapLibre layers](https://maplibre.org/maplibre-style-spec/layers/). 자동 및 Android 실제 검증 결과와 미검증 조건은 TEST_CASE 최신 이력을 따른다.

## 바다 배경·위치 비교 창 (2026-11-07)

지도 배경은 원본 팔레트의 파란 바다색으로 표시하고 물결·구름·비행기·배 조형을 바다 위에만 장식한다. 장식은 터치·접근성 탐색을 가로채지 않으며 확대 시 숨겨 실제 지형/랜드마크와 구분한다. 지리 좌표·축척·선택 레이어 갱신 계약은 유지한다.

위치 입력은 작성 패널의 위치 선택 버튼으로 별도 전체 창을 연다. 지도 선택/장소 검색을 제공하고 인증된 기존 Geoapify 검색→이름·실제 주소 목록→장소 상세 조회→후보 핀/주소 비교→이 위치로 선택 순서를 따른다. 확정 전에는 작성 중인 위치를 바꾸지 않는다. 닫기/뒤로/검색 실패는 사진·기간·위치를 보존하며 늦은 응답은 닫힌 창이나 새 후보를 덮어쓰지 않는다. 주소는 제공자 원문 그대로 표시하고 모의 주소를 실제 검색 결과로 가장하지 않는다. 기존 저장 필수 조건·공개 범위·초안/재시도는 변경하지 않는다. 저장 후 홈 지도에 대표사진 썸네일이 실제 좌표로 즉시 반영되는 것을 실제 이미지 업로드와 재조회로 검증한다.

지도 표시 보완: 초기 카메라는 실제 좌표의 본토·제주 중심 영역(동경 125.6~129.9, 북위 33.1~38.7)을 크게 보여주며, 대한민국 전체 보기에서는 데이터에 포함된 서해 도서·울릉도까지 포함한다. 이동 가능한 영역은 국내 주변으로 제한하고 화면 크기에 맞춰 초기 표시 영역을 자동 계산한다. 확대해도 지역명을 제거하지 않는다. 행정 경계는 기존 2018 자료의 한계가 있으며 좌표를 화면 중앙/도 중심으로 옮겨 정확도를 가장하지 않는다.

## MapLibre 전환 계약 (2026-11-06)

현재 지도·장소 검색·사진 선택 계약은 [TRD의 MapLibre 전환 계약](TRD.md#maplibre-전환-계약-2026-11-06)을 따른다. Google OAuth는 유지한다. 지도 요구사항은 FR-MAPLIBRE-001~005, 사진 선택은 FR-PHOTO-CLOUD-001~003이며 구현과 수용 검증을 구분한다. 원격 migration·함수 배포와 Geoapify 서버 Secret 설정을 적용했다. 기존 날짜별 테스트 이력은 보존하고 최신 결과는 TEST_CASE를 따른다.


## 1. 문서 목적

새 표시명은 여행가봥이며 화면 초안은 `DISAN.md`를 따른다. MapLibre + 로컬 17개 시·도 GeoJSON, 하단 유지 작성 패널, 일방 팔로우·공개 프로필·방문 스탬프를 구현했다. 구현과 검증 범위는 TEST_CASE 최신 실행 결과로 구분한다. 기존 저장·소유권·private/public 정책은 유지한다.

MyTravelDex는 사진과 위치정보를 기반으로 사용자의 여행 기록을 저장하고 지도에서 다시 탐색할 수 있도록 하는 서비스다. 본 문서는 백엔드 우선 MVP의 기능, 보안, 품질, 비용 요구사항을 정의한다.

## 2. 범위

### 2.1 기존 MVP 포함

- Google OAuth 로그인
- 사용자 프로필 생성 및 인증 사용자 식별
- 여행 기록의 생성, 조회, 수정, 삭제
- 여행 기록별 압축 보관 사진 및 썸네일 저장
- 사진 EXIF 기반 촬영일·GPS 추출 지원
- EXIF 누락 시 촬영일·위치 수동 입력
- 위도·경도 및 사람이 읽을 수 있는 장소명 저장
- 여행 기록의 `private`·`public` 공개 상태
- 본인 기록 전체 관리
- 공개 기록은 비로그인·로그인 사용자 모두 조회 가능
- 사용자의 소유권과 공개 상태에 따른 데이터·파일 접근 제어
- 웹과 Android에서 동일한 백엔드 계약 사용

### 2.2 이번 재설계 제외

- 상호 친구 승인, 댓글, 좋아요, 별도 스탬프 보상 아이템
- 프로필 사진 직접 업로드
- 링크 전용 공유
- 실시간 위치 추적 및 백그라운드 위치 수집
- 동영상 업로드
- 여행지 랜덤 추천 데이터베이스
- 시·군·구 이하 상세 행정구역 색칠 및 방문 보상
- 사진 자동 분류·얼굴 인식
- 여행 기록 PDF·앨범 자동 생성

## 3. 기능 요구사항

| ID | 요구사항 | 우선순위 | 완료 기준 |
|---|---|---:|---|
| FR-AUTH-001 | 사용자는 Google OAuth로 로그인할 수 있어야 한다. | Must | 인증 성공 후 서비스 사용자와 연결된다. |
| FR-AUTH-002 | 인증된 사용자는 자신의 프로필을 조회할 수 있어야 한다. | Must | 세션의 사용자 ID와 프로필 ID가 일치한다. |
| FR-TRAVEL-001 | 인증된 사용자는 사진을 하나 이상 포함한 여행 기록을 생성할 수 있어야 한다. | Must | 생성 중에는 `draft`, 사진·기간·위치가 모두 준비되면 `complete`로 전환되고 완료 기록만 일반 목록에 노출된다. |
| FR-TRAVEL-002 | 사용자는 자신의 여행 기록만 수정·삭제할 수 있어야 한다. | Must | 다른 사용자 요청은 거부된다. |
| FR-TRAVEL-003 | 사용자는 자신의 여행 기록 목록과 상세를 조회할 수 있어야 한다. | Must | 비공개 기록을 포함해 본인 기록이 조회된다. |
| FR-TRAVEL-004 | 공개 여행 기록은 소유자가 아닌 사용자도 조회할 수 있어야 한다. | Must | `status = complete AND visibility = public`인 기록만 반환된다. |
| FR-TRAVEL-005 | 사용자는 여행 기록을 `private` 또는 `public`으로 설정할 수 있어야 한다. | Must | 허용된 두 값 이외는 저장되지 않는다. |
| FR-PHOTO-001 | 사용자는 여행 기록에 사진을 하나 이상 업로드해야 한다. | Must | 여행 기록은 하나 이상의 Storage 파일과 DB 메타데이터를 가진다. |
| FR-PHOTO-002 | 원본을 업로드하지 않고 압축 보관 사진과 썸네일을 구분해 저장해야 한다. | Must | EXIF 파싱 후 JPEG 보관본(긴 변 2048px·5 MiB 이하)과 JPEG 썸네일(512px·512 KiB 이하)을 저장하며 작은 이미지는 확대하지 않는다. 기존 original_path는 압축 보관본 경로로 재사용한다. |
| FR-PHOTO-003 | 사진에서 추출한 EXIF 촬영일·GPS를 저장할 수 있어야 한다. | Must | 값이 없으면 null을 허용한다. |
| FR-PHOTO-004 | EXIF가 없는 경우 사용자가 날짜·위치를 입력할 수 있어야 한다. | Must | 수동 입력값이 최종 기록값으로 저장된다. |
| FR-PHOTO-005 | 완료된 여행 기록은 대표사진을 가져야 한다. | Must | 초안은 최대 하나, 완료 시 정확히 하나가 `is_cover = true`이며 미선택 시 표시 순서 첫 사진을 지정한다. |
| FR-TRAVEL-006 | 여러 사진의 촬영일을 여행 기록의 기간 초깃값으로 집계해야 한다. | Must | 최소·최대 촬영 날짜를 제안하고 사용자의 최종 수정값을 저장한다. 모두 없으면 수동 입력을 요구한다. |
| FR-TRAVEL-007 | 여행 기록의 대표 위치는 첫 번째 업로드 사진을 기준으로 정해야 한다. | Must | 첫 사진의 위치를 기본값으로 사용하고, 없으면 사용자가 수동 위치를 입력해야 한다. |
| FR-LOCATION-001 | 여행 기록은 위도·경도와 선택적 장소명을 가질 수 있어야 한다. | Must | 위도·경도 범위가 검증된다. |
| FR-LOCATION-002 | 사용자는 지도에서 위치를 보정할 수 있어야 한다. | Should | 저장 전 좌표를 수정할 수 있다. |
| FR-LOCATION-003 | 여행 기록은 기간과 지역으로 필터링할 수 있어야 한다. | Must | 시작일·종료일과 정규화된 국가·지역·도시 정보로 목록과 지도를 필터링할 수 있다. |
| FR-MAP-001 | 위치 확인·보정은 MapLibre와 서버 Geoapify를 사용한다. | Must | 작성·상세에서 지도 표시와 위치 선택이 가능하다. |
| FR-MAP-002 | 홈은 대한민국 17개 시·도를 구분한 전체 지도여야 한다. | Must | GeoJSON 경계 오프라인 렌더링, 시·도 선택·조회 가능한 완료 기록 집계·빈 지역 안내를 제공한다. 사진 추가는 하단 +에서 시작한다. |
| FR-TRAVEL-008 | 완료되지 않은 여행 기록은 공개 조회에 노출되지 않아야 한다. | Must | `status = complete`이고 필수 조건을 만족한 기록만 타인과 공개 목록에 반환된다. |

## 4. 비기능 요구사항

### vNext UI·소셜 수용 기준의 상태

FR-UI-001~011, FR-PROFILE-001, FR-SOCIAL-001, FR-STAMP-001은 코드와 API에 구현했다. 하위 조건의 검증 완료 여부는 TEST_CASE 최신 실행 절을 따른다. 위 기존 기능 ID를 대체하거나 기존 실행 이력을 완료 처리하는 항목이 아니다. 신규 UI는 숫자 좌표 입력을 노출하지 않지만 내부 좌표 모델과 기존 API의 좌표 검증은 유지한다.

- 공개 프로필은 닉네임 1~30자(공백만 불가)·기본 아바타 또는 동의한 Google 사진이다. 공개 확인 전 기존 이름·사진을 자동 공개하지 않는다. 미설정 작성자는 기본 아바타·여행자로 표시하며 기록 작성을 막지 않는다. 이메일·Auth 메타데이터는 공개 응답에서 제외한다.
- 팔로우는 승인 없는 단방향 관계다. 자기 자신·중복 관계·타인 관계 변경을 차단한다. 관계 목록은 본인만 조회하며 공개 프로필만 검색한다. 닉네임 중복은 허용하고 사용자 ID로 구분한다.
- 홈 기본 범위는 본인의 complete(private 포함)와 팔로잉의 complete/public 합집합이다. 내 기록·친구·공개로 전환하고 비로그인은 공개 완료 기록만 탐색한다. 팔로우 해제가 상대의 public 정책을 바꾸지 않는다.
- 공개 프로필을 숨겨도 공개 기록을 비공개로 바꾸지 않으며 작성자 표시만 기본값으로 바꾼다. 기존 관계 해제는 가능하고 공개 프로필을 다시 확인하기 전 새 팔로우 대상 검색에서는 제외한다.
- Geoapify 장소 검색·place_id 상세 조회·핀 보정의 역지오코딩은 서버를 통한다. 장소명·주소만 표시하고 오류 시 기존 확정 위치와 입력을 유지한다. 유효한 EXIF 위치로 저장하는 기존 흐름을 막지 않는다.

### 생성·편집·삭제 수용 기준

- 기간·대표 위치를 확정한 뒤 `draft`를 생성하고 업로드한다. 일반 목록은 `complete`만 표시하고 초안 복구 조회를 분리한다.
- 첫 사진은 네트워크 업로드 완료 순서가 아니라 사용자가 저장 전에 확정한 `display_order`의 첫 사진이다. 완료 후 순서 변경은 대표 위치·기간을 자동 변경하지 않는다.
- 완료 시 사진은 1~20장, 대표사진은 정확히 하나다. 미지정 시 첫 사진을 자동 선택한다. 마지막 사진 삭제는 거부하고 기록 전체 삭제를 안내한다.
- 완료·대표사진 교체·사진 삭제는 동일한 기록 잠금 아래 처리한다. 타인의 호출·직접 상태 변경·소유자 변경·다른 기록으로 사진 이동을 차단한다. 완료 재호출은 같은 완료 결과를 반환한다.
- 등록된 원본·썸네일의 직접 Storage 삭제·덮어쓰기를 차단한다. 기록·사진 삭제 시 파일 경로와 정리 작업을 DB 트랜잭션으로 먼저 보존한다.
- 정리 작업은 서버에서 재시도하며 이미 삭제된 파일은 성공으로 취급한다. 진행 중 업로드는 정리하지 않고, 취소·실패 후 남은 파일과 장기 미완료 초안도 추적한다.
- 공개 조회 제한은 서버에서 강제한다. 기본 테이블·관계 조회·공개 API·Storage 직접 요청 모두 동일한 공개 범위를 지켜야 한다.
- 공개 지도는 사용자가 확정한 대표 좌표를 제공한다. 원본은 소유자 전용이고 썸네일 URL은 서버가 권한과 최대 300초 만료를 검증한다. 비공개 전환은 신규 접근·발급을 막지만 이미 발급·저장된 파일의 즉시 회수는 보장하지 않는다.
- 새 위치는 생성자가 조회할 수 있고 공개 기록에 연결된 위치만 타인에게 공개한다. 공유 위치는 불변이며 보정 시 새 위치를 연결한다.

### MVP 제한값과 날짜 규칙

다음은 초기 MVP 기본값이며 변경 시 API·테스트를 함께 변경한다.

- 기록당 사진 1~20장, 선택 입력 파일당 최대 20 MiB, 허용 입력 MIME은 `image/jpeg`, `image/png`다. 미지원 형식은 선택 단계에서 안내한다.
- 입력 이미지는 최대 40메가픽셀, 썸네일은 JPEG·긴 변 최대 512px·최대 512 KiB다. 작은 이미지는 확대하지 않는다.
- 제목 최대 100자, 내용 최대 5,000자이며 PostgreSQL 문자 수 기준이다. 일일 업로드 횟수 제한은 MVP에서 두지 않고 파일·사진 수·사용량 알림으로 관리한다.
- EXIF 날짜는 촬영지 현지 달력 날짜를 집계한다. 오프셋이 없으면 원래 날짜를 유지하고 임의 UTC 변환을 하지 않는다. `captured_date`를 집계 기준으로 저장하고 시점을 확정할 수 없으면 `captured_at`은 null이다.
- 수동 기간·대표 위치가 자동 제안값보다 우선한다. 사진 추가·삭제·재정렬 후에는 저장된 기간·위치를 자동 덮어쓰지 않고 사용자가 재확정한다.

### 보안·개인정보

- 모든 소유자 전용 CRUD는 Supabase Auth 세션과 PostgreSQL RLS로 보호한다.
- Storage 파일 경로에는 인증 사용자 식별자를 포함한다.
- 공개 기록의 썸네일만 공개 응답에 포함하고 원본 파일은 인증 또는 짧은 만료시간의 signed URL로 제공한다.
- 공개 응답에서는 `photos`의 EXIF 정밀 좌표와 Storage 원본 경로를 제외한다. 소유자 조회에서만 필요한 메타데이터를 반환한다.
- Google OAuth Client Secret, Supabase service role key, 지도 서버 키는 클라이언트 번들에 포함하지 않는다.
- EXIF GPS는 위치 개인정보로 취급하고 수집·공개 목적을 사용자에게 안내한다.
- 서버 로그에 OAuth 토큰, 원본 이미지 URL, 불필요한 정밀 위치를 남기지 않는다.

### 신뢰성·성능

- 잘못된 인증·권한·입력은 안전한 오류 응답으로 처리한다.
- MVP에서는 Expo 클라이언트가 업로드 전에 사진을 압축하고 썸네일을 생성한다. 서버 측 이미지 처리는 후속 Edge Function 후보로 둔다.
- 목록 화면은 썸네일을 우선 사용하며 원본 다운로드를 강제하지 않는다.
- 이미지 업로드와 DB 저장 실패가 발생하면 고아 파일을 정리할 수 있어야 한다.
- 사진의 EXIF 날짜·위치가 없어도 사용자가 여행 시작일·종료일과 대표 위치를 입력하면 기록을 등록할 수 있어야 한다.
- 여러 사진의 유효한 촬영 날짜 중 최소·최대 날짜를 초깃값으로 제안하고 수동 보정된 최종 기간을 저장해야 한다.
- 첫 번째 사진에 위치가 없으면 다른 사진의 위치를 자동으로 대표 위치로 대체하지 않고 사용자에게 수동 위치를 요구해야 한다.
- 여행 기록은 사진, 여행 기간, 대표 위치가 저장되기 전에는 `complete` 상태로 전환되거나 공개 노출되지 않아야 한다.

### 호환성

- 백엔드는 웹과 Android 클라이언트에서 동일하게 사용한다.
- 웹에서 검증 가능한 UI·REST 흐름과 Android에서만 검증 가능한 권한·딥링크·센서 흐름을 분리한다.
- 추후 iOS 추가를 위해 플랫폼 종속 기능은 클라이언트 어댑터로 격리한다.

## 6. 비용 요구사항

- 개발 초기에는 Supabase Free 플랜 범위에서 동작해야 한다.
- 현재 계획 기준 무료 한도는 DB 500MB, Storage 1GB, Egress 5GB, MAU 50,000명 수준이며 실제 운영 전 요금표를 재확인한다.
- Geoapify 서버 검색의 플랜·쿼터·비용을 확인하고 사용량을 관리한다. 지도 자체는 외부 배경 타일을 요청하지 않는다.
- 무료 한도 초과 시 자동으로 큰 비용이 발생하지 않도록 예산 알림과 사용량 모니터링을 둔다.
- 사진 크기·해상도·기록당 사진 수는 위 MVP 제한값을 적용한다.

## 7. 수용 기준

- 인증되지 않은 사용자는 소유자 전용 데이터를 조회·변경할 수 없다.
- 사용자는 다른 사용자의 비공개 여행 기록을 확인할 수 없다.
- 완료된 공개 여행 기록은 비로그인·로그인 사용자 모두 조회할 수 있고, 공개 응답에 원본 경로와 EXIF 정밀 위치가 포함되지 않는다.
- 다른 사용자는 자신의 ID로 타인의 전체 DB를 조회할 수 없고, 공개된 여행 기록과 연결된 데이터만 조회할 수 있다.
- 사진 메타데이터가 있으면 촬영일·위치가 저장되고, 없으면 수동 입력이 가능하다.
- 원본·썸네일 Storage 경로와 DB 레코드가 일관성을 유지한다.
- 핵심 권한·도메인 테스트가 통과한 후 웹·Android 검증을 진행한다.
- 사진이 없는 `draft`는 공개 목록·공개 상세에 노출되지 않는다.

## 9. 필요한 외부 API

지도는 MapLibre와 번들된 KOSTAT 2018 경계를 사용하므로 Google 지도 API·배경 타일 API를 활성화할 필요가 없다. Google OAuth는 로그인에 유지한다.

장소 검색은 인증된 Edge Function이 Geoapify Geocoding Search·Reverse와 Place Details를 호출한다. 키는 Supabase 서버 Secret만 사용하고 플랜·쿼터·비용을 검토한다. 서버 계약은 API_SPEC를 따른다. 직접 Google Photos API·추가 Photos OAuth는 도입하지 않는다.

## 10. 문서 변경 동기화

요구사항 변경은 다음 순서로 반영한다.

1. 이 문서에 요구사항 ID와 수용 기준을 변경한다.
2. `PRD.md`에 사용자 흐름·제품 정책·MVP 범위를 반영한다.
3. `TRD.md`에 데이터·API·RLS·환경변수·상태 전이를 반영한다.
4. `API_SPEC.md`와 `TEST_CASE.md`에 요청·응답·권한·검증을 반영한다.
5. `AGENTS.md`, `README.md`, `README.local.md`, `planning.md`의 범위·명령어·링크 영향을 확인한다.
6. `.env.example`의 키 추가·삭제·이름 변경 여부를 확인한다.
7. 구현 코드는 문서 동기화 검토가 끝난 후 수정한다.
