# 여행 사진첩 개편

## FR-ALBUM-01 · 사진 보관

새 여행 사진의 보관본은 원래 비율을 유지하고 작은 이미지를 키우지 않으며 가로 최대 1080px, WebP 품질 0.75로 기록한다. 썸네일은 긴 변 512px, 512KiB 이하다. 보관본의 5MiB 상한을 넘으면 같은 품질로 크기를 낮춘다. 촬영일·좌표는 압축 전 원본에서 읽고, 공개 화면에서는 기존 최소 projection과 300초 서명을 사용한다. 기존 JPEG/PNG 읽기·대표 지정·삭제·초안 마무리를 지원한다. 기존 보관본을 변환하지 않는다. 새 Storage 경로는 original.webp와 thumbnail.webp다. 소유자·기록·사진 UUID 및 실제 객체 metadata 검사를 유지한다. DB 호환 마이그레이션을 먼저 적용해야 새 클라이언트를 배포할 수 있다. 압축 중간 파일은 바이트 확보 후, 선택 캐시는 성공/취소 후 정리한다. 재시도에 필요한 선택 사진과 사용자 갤러리 원본은 보존한다.

## FR-ALBUM-02 · 읽고 뒤집는 사진첩

피드는 기존 세로 탐색/무한로드를 유지하며 한 여행 안의 사진은 수평으로 넘긴다. 사진을 누르면 뒷면에서 공개 가능한 여행 정보가 보이고 상세·댓글·공유 등은 별도 버튼으로 접근한다. 도감 첫 화면은 지역 책장이며 지역 책을 열면 같은 형식의 앨범에서 여행을 좌우로 탐색한다. 검색·필터·기존 관리·초안·스탬프 경로를 보존한다. 책등과 책갈피, 종이 가장자리, 사진 모서리와 절제한 서체 대비로 여행 앨범의 모양을 만든다. 책 열기와 카드 뒤집기는 동작 줄이기에서 생략한다. 좌우 버튼, 키보드 및 스크린리더 대안을 제공한다. 기존 테마·언어와 48px 이상의 조작 영역을 유지한다.

## FR-ALBUM-03 · 관리와 준비 상태

자신의 완료 기록만 일괄 관리한다. 대상을 직접 선택하고 개수와 작업을 확인한 뒤 기존 소유자 RLS·삭제 RPC 또는 비공개 변경을 호출한다. 계정 교체 시 이후 요청을 중단하고 성공한 항목을 재전송하지 않는다. 부분 실패와 재조회 실패를 구분한다. 초기 목록·사진만 실제 화면 비율로 자리표시자를 그린다. 갱신은 기존 내용을 유지하고 실패·빈 목록·재시도를 구분한다. 로딩 연출 때문에 입력이나 실제 데이터 표시를 늦추지 않는다.

## FR-ALBUM-04 · 지도 연속성

앱 시작 중 지도 준비를 시작하고 전국/상세에서 동일 카메라를 사용한다. 번들 육지 윤곽을 타일보다 먼저 칠하며 요청 중·오류·재시도마다 윤곽을 껐다 켜지 않는다. 시군구 경계·이름은 상세 배율에서 대비와 크기를 높이고 기존 선택·마커와 입력을 보존한다. 웹에서 지연/실패한 세부타일과 연속 확대·이동 중 육지 표시를 검증한다. GPU·기기 프레임 시간은 별도 측정 대상이다. 웹에서 카메라가 움직일 때 해안선·육지·선택 영역은 새 타일 도착 전부터 현재 위치에 그린다. 줌 8 경계에서 시도 강조를 이어 그리며 같은 기록의 사진은 군집이 바뀌어도 밝기를 유지한다.

## 검증

격리 Supabase Local에서 WebP 등록·완료·서명·삭제와 이전 JPEG 호환을 검증한다. 모바일 폭과 데스크톱 웹에서 책 펼침·뒤집기·넘기기·키보드·동작 줄이기, 소유자 관리와 실패 복구, 타일 지연 중 기저 지도와 UI 연속성을 확인한다. 운영과 Android 빌드는 이번 실행 범위에서 제외한다.

t19c 계획 검토 반영. 서버는 본인 기록·사진 UUID에 한해 이미 올린 포맷·파일 크기를 돌려준다. 이전 JPEG 보관본만 있거나 썸네일까지 있고 등록 전인 경우 그 경로를 이어서 사용한다. WebP 인코더 미지원과 이전 서버는 JPEG 호환 경로를 사용한다. 일괄 작업은 실행 시 고정한 소유자·ID를 확인하며 응답 유실 시 본인 목록에서 반영 여부를 확인한다. 기존 목록은 같은 계정·조회 범위에서만 유지한다. 지도 속도 비교는 같은 화면·타일 지연 조건에서 첫 윤곽과 지연 중 공백을 분리한다.

### 세션을 닫은 뒤 사진 복구

본인 초안에서 `travel_draft_files(record_id)`로 아직 photos에 등록하지 않은 보관본의 원래 사진 UUID를 읽는다. `photo-url`은 `draft_id, photo_id, variant=original`에 대해 같은 소유자 조회가 돌려준 경로만 300초 서명한다. 복구된 JPEG와 WebP의 실제 픽셀 크기를 다시 읽고, 누락된 썸네일만 그 바이트에서 생성한다. 저장이 시작된 사진은 같은 UUID로 자르기를 바꿀 수 없다. 기록에 남은 여행 기간과 대표 위치를 유지하며 사진별 유실된 EXIF를 추측하지 않는다.

웹은 앱 시작 시 번들 경계로 생성한 약 20KB 전국 윤곽 SVG를 브라우저 캐시에 준비한다. 상세 지도 코드는 지도 탭 포커스 또는 지도 진입 시 가져온다. 도감에서 복귀하는 카메라나 지정 좌표로 이동할 때에는 전국 미리보기를 표시하지 않는다. 경계 데이터 갱신 시 `python scripts/build-album-overview.py`로 같은 SVG를 생성한다.

일부 전송된 사진은 복구 시 다시 발견된다. 이 상태에서는 편집과 개별 빼기를 모두 잠그고 초안을 폐기하려는 사용자를 기존 소유자 삭제 확인 창으로 연결한다. 확인 전에는 아무것도 지우지 않는다. 초안을 실제 삭제하면 작성기 쪽의 연결과 임시 선택 파일도 해제한다. 업로드 시작 전의 개별 사진 빼기와 자르기는 계속 사용할 수 있다.

도감과 지도는 현재 계정·조회 범위에서 허용된 같은 기록 목록을 사용한다. 기록과 관계 조회가 성공하면 대표사진 서명이나 작성자 조회가 실패해도 해당 책과 현재 장을 유지한다. 실패한 자료만 재요청하며, 계정·대상·관계 및 기록 권한 변경 시에는 새 결과에 맞춘다. 전송 실패를 정상적인 빈 사진으로 표시하지 않는다.

## FR-ALBUM-05 · 양장 여행 백과와 여행 열람실

지역 책과 열리는 표지는 밤색 가죽, 금박 테두리, 둥근 책등, 두꺼운 종이 단면과 뒷표지가 보이는 양장본이다. 피드는 제목·여행 기간·실제 사진을 앞세운 여행 열람실이다. 좁은 화면에서는 위에서 아래로 읽고 넓은 지면에서는 사진과 글을 펼친 책처럼 나란히 본다. 기고자·작성 시각·팔로우, 좋아요·댓글·저장·공유·상세 진입과 기존 피드 모드·무한 스크롤은 유지한다.

사진 뒷장은 기록의 대표 위치를 ‘여행 위치’로 표시한다. 도감은 현재 허용된 기록의 위치를 쓴다. 공개 피드는 뒷면을 열 때 해당 ID의 complete/public 기록에서 RLS를 거친 대표 장소명·주소·지역명만 읽는다. 사진 EXIF와 정밀 좌표는 요청하지 않는다. 정보 없음과 조회 실패를 구분하고 실패할 때 현재 뒷면에서 재시도한다. 닫기·계정 전환 후 늦은 응답이 이전 장소를 노출하지 않게 한다. 동작 줄이기와 키보드 넘김·뒤집기를 보존한다.

피드 사진의 ‘여행 위치 보기’는 장소명과 주소를 먼저 보여 주며 원고는 바깥 지면에서 계속 읽는다. 도감의 ‘사진 정보·위치 보기’는 여행 기간·제목·본문도 제공한다. 두 화면 모두 ‘사진 앞면 보기’로 돌아간다.
