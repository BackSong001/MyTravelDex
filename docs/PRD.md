# MyTravelDex 제품 요구사항 문서

## Figma 구현 흐름 (2026-11-09)

실제 생성한 자산으로 앱의 백팩·기본 아바타·하단 메뉴·바다 장식을 먼저 교체한다. 홈은 지도 전용을 유지하고 사진/여행/친구/본인 방문 집계는 실제 데이터로 동작한다. 새 테마/한 열 목록/친구 탭/My 및 무료 여행 도구는 FIGMA_IMPLEMENTATION의 순서로 진행한다. 가상 인물·여행 예시를 사용자 계정/기록으로 저장하지 않는다. 시안에서 생략된 요청/수락·유저 ID·검색 정렬·초안/권한 기능도 보존한다.


## 기능 보존과 짧은 화면 개선 (2026-11-08)

다른탭로그아웃/다른계정로그인후앞계정사진·초안·상세를다음사용자에게보여주지않는다. 동일계정세션갱신은입력을지우지않는다. 서버초안·기록/Storage는건드리지않는다. 기능baseline자동검사→실패재현/최소수정→t14단계리뷰→전체회귀→실제Android순서로검증한다.

디자인방향은하늘/민트/코랄과시스템고딕을유지한간결한여행사진첩이다. 12/16/20여백과사진위계를재사용하고짧은높이에상단브랜드/하단탭을조밀하게배치해본문이더보이게한다. 검색어만지우는동작은정렬값을변경하지않으며검색실패와첫여행없음을구분한다. motion은기존사용자반응/동작줄이기계약만사용한다. 기존계정삭제정책/Play·실기기외부수용미완료를전체기능통과로과장하지않는다.


## 친구 추가에 사용하는 유저 ID (2026-11-08)

모든사용자의짧은ID는6자리영문·숫자조합의“유저 ID”다. My와친구탭에같은ID를표시하고닉네임검색/전체공개목록/친구요청·수락을유지한다. 새초대링크는유저ID를사용하며입력소문자는대문자로정규화한다. 기존숫자ID/UUID초대도같은사람을찾되새ID를표시한다. ID는인증수단이아니다. 이전ID를삭제/타인에게재할당하지않는다.


## 사진·지역명을 가리지 않는 지도 (2026-11-08)

산·풀 장식을 홈/상세/위치 선택 지도에서 제거해 사진과 지역명을 우선한다. 바다 장식과 경계·카메라·썸네일 군집은 유지한다. 친구ID는 현재 서버발급6자리숫자로중복을차단하며 영숫자혼합여부와기존ID정책은 별도검토한다.


## 짧은 친구 ID와 전체 목록 (2026-11-08)

My 프로필에서 6자리 숫자 친구 ID를 확인하고 친구 추가 화면에서 같은 닉네임의 여행자를 구분한다(FR-FRIEND-005~006). 친구 탭 진입 시 공개 여행자 목록을 바로 보여주며 다음/이전으로 전체를 탐색하고 새로고침·닉네임/짧은 ID 검색을 제공한다. 빈 검색은 전체 공개 목록이며 기존 친구/대기 요청도 표시하고 해당 관계의 버튼을 유지한다. 기존 UUID 링크는 호환한다. 공개를 해제한 계정의 개인정보는 목록에서 제외하고 기존 관계는 기본 여행자 표시로 유지한다. 산/풀은 채움과 입체 면을 없앤 선 장식으로 간소화한다(FR-UI-016).

## 사진에서 기간·장소 채우기 (2026-11-08)

FR-PHOTO-LOCATION-001~003: 사진을 고르면 촬영일 범위와 첫 사진 GPS를 자동 제안하되 이미 편집한 값은 유지한다. 장소 영역은 검색바이며 GPS가 있으면 촬영 좌표와 조회된 장소/주소, 없으면 빈 검색 안내를 표시한다. 눌러 별도 검색창에서 검색→후보/핀 확인→확정한다. 취소/연결 실패 시 사진·기간·기존 위치를 유지한다. 위치를 얻지 못하면 직접 확정해야 저장할 수 있다. metadata가 없는 클라우드/제한된 사진을 실제 촬영일/위치 수신 성공으로 표시하지 않는다. 내용 채우기는 장소 검색바의 정보이며 여행 본문 자동생성은 범위 밖이다.

## 추천 친구·사진 묶음·검색 흐름 (2026-11-08)

FR-FRIEND-004·FR-UI-013~015는 2026-11-08 사용자 요청으로 승인된 변경이다. 친구 탭 진입 시 공개 프로필 최대50명을 추천하고 추천 새로고침을 제공한다. 같은 닉네임은 UUID 친구 ID로 구분하고 요청/상대 수락 후 친구 범위의 공개 완료 여행을 본다. 전체 유저 개인정보 조회·비공개 사진 공유·자동 친구 생성은 하지 않는다. 새 계정 두 개로 실제 사진 업로드→ID 요청→수락→친구 공개 사진 조회·비공개 제외를 검증한다.

도감은 범위→검색→기본 최신 여행 순 사진 목록을 제공한다. 필터 패널은 지역/시작일의 양방향 정렬과 초기화이며 기존 날짜 범위 입력을 대체한다. 검색/정렬은 도감에만 작용해 홈 지도와 My 방문 집계는 변하지 않는다. 군집은 사진 묶음으로 표시하고 가로 사진 선택과 빠른 목록을 함께 제공한다. 산/풀은 장난감 지도 같은 장식으로 지역 데이터와 구분하며 손가락 조작·사진 마커를 방해하지 않는다.

## 사진첩 디자인·반응 효과 (2026-11-07)

FR-UI-012·DISAN 상단을 따른다. 홈은 지도, 도감은 사진과 제목을 먼저 보여주고 범위 선택은 유지하되 지역·기간 입력은 필터 버튼으로 펼친다. 필터를 접어도 입력/적용 값은 보존한다. 사진·버튼·탭은 눌림/호버/포커스로 상태를 알리고 작성/미리보기 전환은 짧게 반응한다. 큰 화면에서는 사진 열 수와 내용 폭을 조절하고 좁은 화면·큰 글꼴에서는 줄바꿈한다. 모션 설정 조회나 애니메이션이 로그인/저장/내용 표시를 막지 않는다. 기존 친구 요청·초대·작성/사진·권한 계약은 유지한다.

## 친구 요청·초대 흐름 (2026-11-07)

기존 일방 팔로우에 친구 요청을 추가한다(FR-FRIEND-001~003). 친구 탭에서 자신의 UUID 친구 코드/설치 앱 초대 링크를 공유하거나 닉네임·코드로 공개 여행자를 검색한다. 보내기→받은 요청 수락/거절, 보낸 요청 취소, 수락한 친구 삭제를 제공한다. 같은 이름은 코드로 구분한다. 초대 링크는 검색 후보를 열 뿐 요청/수락을 자동 처리하지 않는다. 공개 프로필을 숨긴 상대의 관계는 기본 여행자 표시와 코드로 유지하고 원본 프로필을 공개하지 않는다.

수락한 친구의 완료된 공개 여행을 친구 지도·도감에서 조회한다. 친구 삭제와 팔로우 해제는 각각의 관계만 제거하며 공개 여행의 일반 접근 권한은 유지된다. 기존 팔로우를 상호 동의로 간주하지 않는다. 초대는 현재 설치된 Android 앱의 scheme 링크이며 미설치자를 위한 스토어/웹 fallback·주소록 초대는 추가하지 않는다. 기존 화면 스타일을 재사용하며 대규모 디자인 변경은 하지 않는다.

Android 제출 준비는 NFR-RELEASE-001을 따른다. 업로드 키로 서명한 로컬 AAB 생성은 사용자에게 배포하는 단계가 아니며, 실제 제출·운영 환경 변경은 승인 후 진행한다. 기존 시험용 APK는 계속 개발 서명을 사용한다.

지도 군집을 연 상태에서 조회 범위가 바뀌거나 기록이 삭제되면 현재 범위에서 제외된 여행은 선택 목록에서도 사라진다. 제목 등 갱신된 기록은 최신 내용으로 선택하며 지도 위치·확대 수준은 유지한다(FR-UI-004, TC-MAPLIBRE-007).

## 밝은 파스텔 UI 개편 (2026-11-07)

기존 기능 계약을 유지하는 디자인 개편이다. 원본 팔레트/스토리보드는 보존하고 theme 의미 토큰으로 하늘 #EFFAFF·민트 #E9F8F1·기존 코랄을 확장한다. 홈 발자국 배지만 제거하고 My 스탬프는 유지한다. 네 지도 범위는 선택기 하나로 통합하고 로그인/계정은 My로 접근한다. 지역명은 상자/체크 없는 회색 글자로 줌 5~9에서 11~15로 변화하며 충돌과 글꼴 확대를 고려한다. 기존 17개 실제 경계 아래 얕은 그림자·구분 레이어를 추가하되 좌표/경계와 선택 강조는 보존한다.

지도 기록은 최대 화면 높이 60%의 하단 사진 패널로 열고 대표사진 우선 가로 갤러리, 작은 제목/날짜, 기존 content의 두 줄 한줄평을 보여준다. 상세에서 전체 내용과 같은 갤러리를 제공한다. 사진 순서/대표 지정/삭제/권한/서명 URL 재발급은 유지하고 관리 동작을 접어 정리한다. 사진 아래 이름은 숨기고 공개 동의된 기존 프로필 사진 또는 로컬 여행 캐릭터 SVG만 표시한다. 접근성 작성자 이름과 친구/My의 이름은 유지한다. 전체 화면과 시작 스플래시·로그인 진입은 밝은 테마로 통일한다.

반응형은 320~1280 폭·가로·fontScale 1/1.5/2, 안전 영역/키보드에 대응하며 최소 48dp 터치·일반 텍스트 대비 4.5:1을 유지한다. 사용자 반응에만 짧은 효과를 쓰고 동작 줄이기를 존중한다. API/DB/RLS/migration 변경 없이 기존 조회·사진 압축·Storage·OAuth·EXIF·초안·소유자 권한을 사용한다. 참고: [Polarsteps](https://www.polarsteps.com/), [Mapicus](https://www.mapicus.app/), [MapLibre layers](https://maplibre.org/maplibre-style-spec/layers/). 자동 및 Android 실제 검증 결과와 미검증 조건은 TEST_CASE 최신 이력을 따른다.

## 바다 배경·위치 비교 창 (2026-11-07)

지도 배경은 원본 팔레트의 파란 바다색으로 표시하고 물결·구름·비행기·배 조형을 바다 위에만 장식한다. 장식은 터치·접근성 탐색을 가로채지 않으며 확대 시 숨겨 실제 지형/랜드마크와 구분한다. 지리 좌표·축척·선택 레이어 갱신 계약은 유지한다.

위치 입력은 작성 패널의 위치 선택 버튼으로 별도 전체 창을 연다. 지도 선택/장소 검색을 제공하고 인증된 기존 Geoapify 검색→이름·실제 주소 목록→장소 상세 조회→후보 핀/주소 비교→이 위치로 선택 순서를 따른다. 확정 전에는 작성 중인 위치를 바꾸지 않는다. 닫기/뒤로/검색 실패는 사진·기간·위치를 보존하며 늦은 응답은 닫힌 창이나 새 후보를 덮어쓰지 않는다. 주소는 제공자 원문 그대로 표시하고 모의 주소를 실제 검색 결과로 가장하지 않는다. 기존 저장 필수 조건·공개 범위·초안/재시도는 변경하지 않는다. 저장 후 홈 지도에 대표사진 썸네일이 실제 좌표로 즉시 반영되는 것을 실제 이미지 업로드와 재조회로 검증한다.

## MapLibre 전환 계약 (2026-11-06)

현재 지도·장소 검색·사진 선택 계약은 [TRD의 MapLibre 전환 계약](TRD.md#maplibre-전환-계약-2026-11-06)을 따른다. Google OAuth는 유지한다. 지도 요구사항은 FR-MAPLIBRE-001~005, 사진 선택은 FR-PHOTO-CLOUD-001~003이며 구현과 수용 검증을 구분한다. 원격 migration·함수 배포와 Geoapify 서버 Secret 설정을 적용했다. 기존 날짜별 테스트 이력은 보존하고 최신 결과는 TEST_CASE를 따른다.


여행가봥 재설계 초안은 `DISAN.md`를 따른다. 스토리보드·컬러 기반 UI와 다음 절의 소셜 기능을 구현했다. 기존 기록 작성·공유·권한·사진 제한·초안 복구 정책을 유지한다. 최종 수용 여부는 TEST_CASE 실행 증거로 판단한다.

## 여행가봥 제품 흐름

사용자는 사진으로 여행 기록을 간편하게 추가·관리하고, 실제 지도에서 방문 지역을 확인하며, 도감과 방문 스탬프를 모으고 팔로우한 사람의 공개 기록을 구경한다.

1. 시작: 백팩·여행가봥 스플래시 → 로컬 세션 준비 → 로그인/홈이다. Google 동의와 목록 네트워크 때문에 스플래시를 지연시키지 않는다.
2. 홈: 내 complete와 팔로잉의 complete/public을 함께 보여준다. 내 기록·친구·공개 범위를 바꿀 수 있고 비로그인 미리보기는 공개 기록이다. 기본 지도의 확대/축소·시·도 색상·축척별 명칭은 DISAN을 따른다.
3. 기록 탐색: 대표 위치의 대표사진 마커 아래에 아바타·닉네임을 표시한다. 누르면 기간·장소·작성자 미리보기, 지역을 누르면 해당 지역 도감으로 이어진다. 공개 프로필 미설정 작성자는 기본 표시한다.
4. 추가: 하단 + → 아래에서 올라오는 패널 → 사진 선택 → 자동 기간/첫 사진 위치 확인 → 정보·공개 범위·대표사진 확정 → 기존 저장/완료 흐름이다. 하단 홈·여행도감·+·친구·My를 유지한다. 시스템 갤러리/권한 창은 예외다.
5. 패널: 탭 전환 시 최소화해 입력을 유지하고 +로 재개한다. 폐기는 확인하며 저장 실패·중복 제출·초안 복구를 기존 계약대로 처리한다. 다른 탭을 보는 중 저장이 끝나도 강제 화면 이동 없이 완료 안내를 제공한다.
6. 위치: 숫자 위도·경도 입력 없이 Geoapify 장소 검색 결과의 실제 주소를 선택한다. 서버 place_id 상세 조회 후 핀을 보정하면 역지오코딩한다. 유효한 EXIF 위치·기존 확정값을 보존하고, 검색 문자열만으로 장소를 확정하거나 오류 시 주소를 추측하지 않는다.
7. 도감: 지역·기간·조회 범위를 한 줄 필터로 적용/해제하며 큰 글꼴·좁은 화면은 가로 스크롤한다. 완료 기록과 임시저장 복구를 구분한다.
8. 친구: 공개 닉네임 검색 → 일방 팔로우/해제 → 팔로잉 목록/지도 보기다. 승인 요청·비공개 공유·이메일 검색은 없다. 팔로우 해제는 상대의 공개 정책을 변경하지 않는다.
9. My: 공개용 닉네임·기본 아바타 또는 동의한 Google 사진을 설정한다. 공개 확인 전 기존 프로필을 자동 노출하지 않으며 프로필 미설정으로 기록 작성을 막지 않는다. 이메일은 공개하지 않는다.
10. 스탬프: 본인 complete의 대표 위치로 방문한 국내 시·도를 계산한다. 친구·draft·해외를 제외하고 마지막 기록 삭제/위치 변경에 따라 재계산한다. 별도 보상 아이템이나 영구 획득은 없다.

현재 기능과 신규 UI의 회귀·수용을 분리한다. 본문 MVP 제외는 기존 구현 단계에 대한 내용이며, 이번 계획에는 일방 팔로우·공개 프로필·17개 방문 스탬프를 추가한다. 상세 한계·반응형·애니메이션 감소·컬러 대비는 DISAN과 REQUIREMENT의 FR-UI-001~011을 따른다.

## 1. 제품 개요

MyTravelDex는 갤러리 사진의 촬영일과 위치정보를 활용해 사용자의 여행 기록을 저장하고, 지도에서 방문 경험을 다시 탐색하게 하는 여행도감 서비스다.

## 2. 문제와 목표

### 문제

- 여행 사진은 휴대폰에 쌓이지만 장소와 기억을 함께 정리하기 어렵다.
- 사진을 시간순으로 보는 것만으로는 방문 지역과 여행 흐름을 파악하기 어렵다.
- 여행 기록을 작성하는 과정이 번거로워 지속적인 기록으로 이어지기 어렵다.

### 제품 목표

- 사진을 선택하는 것만으로 여행 기록 작성의 시작 비용을 낮춘다.
- 촬영일·위치정보를 활용해 기록 입력을 줄인다.
- 지도와 기록을 연결해 사용자가 자신의 여행 이력을 쉽게 재탐색하게 한다.
- 사용자가 원하는 기록만 공개해 공유 가능성을 확보한다.

## 3. 대상 사용자

- 여행 사진을 보관하지만 별도 기록을 거의 남기지 않는 사용자
- 방문한 지역을 지도에서 한눈에 보고 싶은 사용자
- 사진과 글을 책이나 도감처럼 다시 감상하고 싶은 사용자
- 본인의 여행 기록을 선택적으로 공개하고 싶은 사용자

## 4. MVP 성공 기준

- 사용자가 Google 로그인 후 사진 한 장 이상, 여행 기간, 여행 위치를 입력해 여행 기록을 등록할 수 있다.
- EXIF가 있는 사진은 촬영일·위치 입력을 줄여준다.
- EXIF가 없는 사진도 사용자가 날짜와 위치를 직접 입력해 등록할 수 있다.
- 사용자가 지도에서 기록 위치를 확인하고 수정할 수 있다.
- 비공개 기록이 다른 사용자에게 노출되지 않는다.
- 공개 기록은 다른 사용자가 조회할 수 있다.
- 비로그인 사용자도 완료된 공개 기록을 조회할 수 있지만, 공개 응답에서 원본 경로와 EXIF 정밀 좌표를 볼 수 없다.
- 웹 테스트와 Android 테스트 결과를 구분해 기능 완성 여부를 판단한다.

## 5. 핵심 사용자 흐름

### 5.1 Google 로그인

1. 사용자가 로그인 화면을 연다.
2. Google 로그인 버튼을 선택한다.
3. Google OAuth 동의를 완료한다.
4. 앱이 Supabase 세션을 확인한다.
5. 최초 사용자라면 프로필을 생성하거나 연결한다.
6. 여행 기록 목록으로 이동한다.

실패 시 사용자는 로그인 실패 원인과 재시도 방법을 확인할 수 있어야 한다.

### 5.2 사진 기반 여행 기록 등록

1. 사용자가 새 여행 기록을 선택한다.
2. 갤러리에서 사진을 한 장 이상 선택한다.
3. 앱이 EXIF 촬영일·GPS를 읽는다.
4. 읽은 값을 사용자에게 보여준다.
5. 값이 없거나 잘못된 경우 사용자가 날짜·위치를 수정한다.
6. 앱이 사진들의 유효한 촬영일 중 가장 이른 날짜와 가장 늦은 날짜를 시작일·종료일 초깃값으로 적용한다.
7. 앱이 첫 번째 사진의 위치를 대표 여행 위치 초깃값으로 적용한다.
8. 촬영일이 없으면 시작일·종료일을, 첫 사진 위치가 없으면 대표 위치를 사용자가 수동 입력한다.
9. 사용자가 필수 여행 기간과 대표 여행 위치를 확정한다.
10. 사용자가 선택적으로 제목, 내용, 공개 상태를 입력한다.
11. 사용자가 대표사진을 선택하거나 앱이 첫 번째 사진을 기본 대표사진으로 지정한다.
12. 앱이 `draft` 여행 기록을 만들고 압축 보관본·썸네일을 업로드한다.
13. 사진 메타데이터를 저장한 뒤 필수 조건을 검증하고 `complete`로 전환한다.
14. 업로드나 검증이 실패하면 완료 기록으로 노출하지 않고 재시도·정리한다.
15. 저장 완료 후 상세 화면과 지도 위치를 표시한다.

### 5.3 위치 보정

1. 앱이 EXIF GPS 또는 현재 위치를 초기값으로 표시한다.
2. 사용자가 지도에서 위치를 이동하거나 새 위치를 선택한다.
3. 앱이 위도·경도와 선택적 장소명을 저장한다.

위치 권한이 거부되거나 EXIF GPS가 없더라도 수동 지도 선택은 가능해야 한다.

### 5.4 공개·비공개 전환

- 기본 공개 상태는 `private`다.
- 사용자는 본인 기록의 공개 상태를 `public`으로 변경할 수 있다.
- 다시 `private`로 변경하면 타인 조회가 차단된다.
- 전환 후 신규 조회·URL 발급은 차단한다. 이미 발급·다운로드된 파일은 즉시 회수할 수 없으며 signed URL 만료와 캐시 한계를 공개 전에 안내한다.
- 일방 팔로우는 private/public 외 공개 등급을 추가하지 않으며 링크 전용 공개는 제외한다.

### 5.5 공개 여행 기록 조회

- 공개 상태인 기록만 탐색 결과에 노출한다.
- 비공개 기록은 검색·목록·상세 어느 경로에서도 타인에게 노출하지 않는다.
- 다른 사용자는 공개 기록을 조회할 수 있지만 수정·삭제할 수 없다.
- 친구 지도는 팔로잉의 complete/public으로 별도 제한하며 전체 공개 지도로 대체해 완료 처리하지 않는다.

## 6. 제품 정책

### 사진

- 여행 기록에는 사진이 최소 한 장 있어야 한다.
- 사진은 기록당 최대 20장, JPEG·PNG 원본당 최대 20 MiB·40메가픽셀이다. 제목 100자·내용 5,000자 제한을 적용한다.
- 완료 후 마지막 사진은 단독 삭제할 수 없다. 대표사진 삭제 시 남은 표시 순서의 첫 사진으로 교체한다.
- 첫 사진은 사용자가 확정한 표시 순서 기준이며 업로드 속도와 관계없다. 대표사진 교체는 대표 위치를 바꾸지 않는다.
- 사용자 선택에 따라 새 업로드의 원본은 보존하지 않는다. EXIF를 먼저 읽고 2048px·5 MiB 이하 JPEG 보관본과 512px·512 KiB 이하 JPEG 썸네일만 저장한다. 기존 저장 사진은 자동 변환·삭제하지 않는다.
- EXIF는 선택적으로 읽는다.
- EXIF가 없으면 수동 입력을 허용한다.
- 사진 중 최대 한 장을 대표사진으로 지정하며, 대표사진은 여행도감 목록과 상세 표지에 사용한다.
- 완료 시 대표사진은 정확히 한 장이다. 중복 교체·삭제 요청에도 이 조건을 유지한다.
- 대표사진을 별도로 선택하지 않으면 첫 번째 업로드 사진을 대표사진으로 사용한다.
- 사용자가 업로드 전에 사진을 취소할 수 있어야 한다.

### 여행 기록 필수 정보

- 여행 기간은 필수이며 `start_date`와 `end_date`를 저장한다.
- 사진 촬영일이 있으면 가장 이른 날짜와 가장 늦은 날짜를 자동 적용한다.
- 촬영지 현지 날짜를 초깃값으로 제안하고 수동 수정값을 최종 저장한다. 시간대가 없는 EXIF를 임의 UTC로 해석하지 않는다.
- 저장 후 사진 추가·삭제·순서 변경은 기간·대표 위치를 자동 덮어쓰지 않는다.
- 사진 촬영일이 전혀 없으면 사용자가 시작일과 종료일을 입력한다.
- 대표 여행 위치는 위도·경도가 필수이며 장소명은 선택이다.
- 대표 위치는 첫 번째 업로드 사진의 위치를 우선 사용한다. 첫 사진에 위치가 없으면 수동 입력을 요구한다.
- 여행 제목과 내용은 선택이다.
- 생성 중인 기록은 `draft`, 사용자에게 완료된 여행으로 표시되는 기록은 `complete` 상태다. `draft`는 소유자만 복구·삭제할 수 있다.
- 일반 목록과 초안 복구를 분리한다. 초안은 마지막 활동 후 24시간 동안 복구할 수 있고 만료되면 재작성을 안내한다.
- 여행지도와 여행도감은 여행 기간과 국가·지역·도시 정보로 필터링할 수 있어야 한다.

### 위치정보

- 위치정보 수집 목적을 안내한다.
- 사용자가 위치 권한을 거부해도 기록 작성은 가능해야 한다.
- 공개 기록의 위치 정밀도 공개 여부는 후속 정책으로 확장할 수 있도록 설계한다.
- MVP 공개 지도는 사용자가 확정한 대표 좌표를 표시한다. 사진별 EXIF 정밀 좌표와 원본 파일은 소유자 전용이다.
- MVP 공개 응답에는 대표 위치의 표시용 정보와 썸네일만 포함하고, 원본 경로와 사진 EXIF 정밀 좌표는 포함하지 않는다.

### 오류와 권한 거부

- 로그인 취소, 권한 거부, 업로드 실패, 네트워크 오류를 구분해 안내한다.
- 실패한 업로드는 재시도할 수 있어야 한다.
- 부분 저장으로 인해 사진만 남거나 기록만 남는 상황은 정리 절차로 처리한다.

## 8. 테스트 관점의 제품 수용 기준

- 실제 기기의 GPS와 사진 메타데이터

웹 테스트 통과만으로 Android 기능을 완료한 것으로 간주하지 않는다.

## 9. 초기 설정과 제품 기능의 관계

### Supabase

- Supabase Auth는 사용자 인증과 세션을 담당한다.
- Supabase PostgreSQL은 프로필, 여행 기록, 위치, 사진 메타데이터를 저장한다.
- Supabase Storage는 압축 보관본과 썸네일을 저장한다.
- PostgREST와 RLS는 사용자별 데이터 접근을 제어한다.

### Google OAuth

- Google OAuth는 로그인 수단으로만 사용한다.
- Google 계정의 비밀번호를 MyTravelDex가 직접 수집하지 않는다.
- 로그인 취소·실패 시 사용자가 재시도할 수 있는 상태를 제공한다.

### MapLibre·Geoapify

- 홈·작성·상세는 MapLibre와 로컬 17개 시·도 Polygon을 사용한다. 배경 타일은 없으며 실패 시 국내 GeoJSON + SVG 대체 보기를 제공한다. 검색·상세·주소 보완은 서버 Geoapify가 담당한다.
- MVP에서는 Routes, Navigation, Street View를 사용하지 않는다.
- 지도 API 실패 시 기존 확정 위치·유효 EXIF·작성 입력과 대체 보기/재시도를 보존한다. vNext는 숫자 좌표 입력 대신 검색·핀 보정을 사용한다.

## 10. 초기 설정 실패에 대한 사용자 경험

| 상황 | 사용자 경험 |
|---|---|
| Google 로그인 취소 | 로그인 화면에 머물고 재시도 버튼을 제공한다. |
| OAuth 설정 오류 | 원문 오류를 직접 노출하지 않고 로그인 재시도 안내를 제공한다. |
| 원본 사진 권한 거부 | 기본 시스템 사진 선택을 제공하고 메타데이터가 없으면 기간·장소 보정을 안내한다. |
| 위치 권한 거부 | 사진·기록 등록은 허용하고 지도에서 수동 위치 선택을 제공한다. |
| 지도 렌더링·Geoapify 실패 | 지도 오류 상태와 재시도 버튼을 표시한다. |
| Storage 업로드 실패 | 기록 저장을 완료하지 않고 업로드 재시도를 제공한다. |
| 네트워크 오류 | 입력 내용을 유지하고 연결 복구 후 다시 시도하게 한다. |
