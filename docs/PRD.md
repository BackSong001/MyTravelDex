# MyTravelDex 제품 요구사항 문서

## 1. 제품 개요

MyTravelDex는 갤러리 사진의 촬영일과 위치정보를 활용해 사용자의 여행 기록을 저장하고, 지도에서 방문 경험을 다시 탐색하게 하는 여행도감 서비스다.

## 2. 문제와 목표

### 문제

- 여행 사진은 휴대폰에 쌓이지만 장소와 기억을 함께 정리하기 어렵다.
- 사진을 시간순으로 보는 것만으로는 방문 지역과 여행 흐름을 파악하기 어렵다.
- 여행 기록을 작성하는 과정이 번거로워 지속적인 기록으로 이어지기 어렵다.

### 제품 목표

- 사진을 선택하는 것만으로 여행 기록 작성의 시작 비용을 낮춘다.
- 촬영일·위치정보를 활용해 기록 입력을 줄인다.
- 지도와 기록을 연결해 사용자가 자신의 여행 이력을 쉽게 재탐색하게 한다.
- 사용자가 원하는 기록만 공개해 공유 가능성을 확보한다.

## 3. 대상 사용자

- 여행 사진을 보관하지만 별도 기록을 거의 남기지 않는 사용자
- 방문한 지역을 지도에서 한눈에 보고 싶은 사용자
- 사진과 글을 책이나 도감처럼 다시 감상하고 싶은 사용자
- 본인의 여행 기록을 선택적으로 공개하고 싶은 사용자

## 4. MVP 성공 기준

- 사용자가 Google 로그인 후 사진 한 장 이상, 여행 기간, 여행 위치를 입력해 여행 기록을 등록할 수 있다.
- EXIF가 있는 사진은 촬영일·위치 입력을 줄여준다.
- EXIF가 없는 사진도 사용자가 날짜와 위치를 직접 입력해 등록할 수 있다.
- 사용자가 지도에서 기록 위치를 확인하고 수정할 수 있다.
- 비공개 기록이 다른 사용자에게 노출되지 않는다.
- 공개 기록은 다른 사용자가 조회할 수 있다.
- 웹 테스트와 Android 테스트 결과를 구분해 기능 완성 여부를 판단한다.

## 5. 핵심 사용자 흐름

### 5.1 Google 로그인

1. 사용자가 로그인 화면을 연다.
2. Google 로그인 버튼을 선택한다.
3. Google OAuth 동의를 완료한다.
4. 앱이 Supabase 세션을 확인한다.
5. 최초 사용자라면 프로필을 생성하거나 연결한다.
6. 여행 기록 목록으로 이동한다.

실패 시 사용자는 로그인 실패 원인과 재시도 방법을 확인할 수 있어야 한다.

### 5.2 사진 기반 여행 기록 등록

1. 사용자가 새 여행 기록을 선택한다.
2. 갤러리에서 사진을 한 장 이상 선택한다.
3. 앱이 EXIF 촬영일·GPS를 읽는다.
4. 읽은 값을 사용자에게 보여준다.
5. 값이 없거나 잘못된 경우 사용자가 날짜·위치를 수정한다.
6. 앱이 사진들의 유효한 촬영일 중 가장 이른 날짜와 가장 늦은 날짜를 시작일·종료일 초깃값으로 적용한다.
7. 앱이 첫 번째 사진의 위치를 대표 여행 위치 초깃값으로 적용한다.
8. 촬영일이 없으면 시작일·종료일을, 첫 사진 위치가 없으면 대표 위치를 사용자가 수동 입력한다.
9. 사용자가 필수 여행 기간과 대표 여행 위치를 확정한다.
10. 사용자가 선택적으로 제목, 내용, 공개 상태를 입력한다.
11. 사용자가 대표사진을 선택하거나 앱이 첫 번째 사진을 기본 대표사진으로 지정한다.
12. 원본·썸네일을 업로드한다.
13. 여행 기록과 사진 메타데이터를 저장한다.
14. 저장 완료 후 상세 화면과 지도 위치를 표시한다.

### 5.3 위치 보정

1. 앱이 EXIF GPS 또는 현재 위치를 초기값으로 표시한다.
2. 사용자가 지도에서 위치를 이동하거나 새 위치를 선택한다.
3. 앱이 위도·경도와 선택적 장소명을 저장한다.

위치 권한이 거부되거나 EXIF GPS가 없더라도 수동 지도 선택은 가능해야 한다.

### 5.4 공개·비공개 전환

- 기본 공개 상태는 `private`다.
- 사용자는 본인 기록의 공개 상태를 `public`으로 변경할 수 있다.
- 다시 `private`로 변경하면 타인 조회가 차단된다.
- MVP에서는 친구, 팔로워, 링크 전용 공개를 제공하지 않는다.

### 5.5 공개 여행 기록 조회

- 공개 상태인 기록만 탐색 결과에 노출한다.
- 비공개 기록은 검색·목록·상세 어느 경로에서도 타인에게 노출하지 않는다.
- 다른 사용자는 공개 기록을 조회할 수 있지만 수정·삭제할 수 없다.
- MVP에는 친구·팔로워 관계가 없으므로 “친구 여행지도”는 친구 기능 도입 전까지 공개 여행지도 조회로 정의한다.

## 6. 제품 정책

### 사진

- 여행 기록에는 사진이 최소 한 장 있어야 한다.
- 원본은 보존하고 목록·미리보기에는 썸네일을 사용한다.
- EXIF는 선택적으로 읽는다.
- EXIF가 없으면 수동 입력을 허용한다.
- 사진 중 최대 한 장을 대표사진으로 지정하며, 대표사진은 여행도감 목록과 상세 표지에 사용한다.
- 대표사진을 별도로 선택하지 않으면 첫 번째 업로드 사진을 대표사진으로 사용한다.
- 사용자가 업로드 전에 사진을 취소할 수 있어야 한다.

### 여행 기록 필수 정보

- 여행 기간은 필수이며 `start_date`와 `end_date`를 저장한다.
- 사진 촬영일이 있으면 가장 이른 날짜와 가장 늦은 날짜를 자동 적용한다.
- 사진 촬영일이 전혀 없으면 사용자가 시작일과 종료일을 입력한다.
- 대표 여행 위치는 위도·경도가 필수이며 장소명은 선택이다.
- 대표 위치는 첫 번째 업로드 사진의 위치를 우선 사용한다. 첫 사진에 위치가 없으면 수동 입력을 요구한다.
- 여행 제목과 내용은 선택이다.
- 여행지도와 여행도감은 여행 기간과 국가·지역·도시 정보로 필터링할 수 있어야 한다.

### 위치정보

- 위치정보 수집 목적을 안내한다.
- 사용자가 위치 권한을 거부해도 기록 작성은 가능해야 한다.
- 공개 기록의 위치 정밀도 공개 여부는 후속 정책으로 확장할 수 있도록 설계한다.

### 오류와 권한 거부

- 로그인 취소, 권한 거부, 업로드 실패, 네트워크 오류를 구분해 안내한다.
- 실패한 업로드는 재시도할 수 있어야 한다.
- 부분 저장으로 인해 사진만 남거나 기록만 남는 상황은 정리 절차로 처리한다.

- 친구·팔로워

## 8. 테스트 관점의 제품 수용 기준

### 웹에서 검증

- 로그인 UI와 OAuth 시작 흐름
- 기록 등록·수정·삭제 화면
- 사진 업로드 UI
- EXIF 표시와 수동 수정 UI
- 지도 표시와 위치 선택 UI
- 공개·비공개 전환
- 목록·상세 화면
- 오류·권한 거부 UI
- 반응형 레이아웃

### Android Studio에서 검증

- 실제 앱 빌드·실행
- Google OAuth 딥링크 복귀
- 갤러리·카메라 권한
- EXIF 있는 사진과 없는 사진
- 정확한 위치·대략적 위치 권한
- 실제 지도 현재 위치
- 앱 재실행 후 세션 유지
- 회전·다양한 화면 크기
- 네트워크 불안정·재시도
- 실제 기기의 GPS와 사진 메타데이터

## 9. 초기 설정과 제품 기능의 관계

### Supabase

- Supabase Auth는 사용자 인증과 세션을 담당한다.
- Supabase PostgreSQL은 프로필, 여행 기록, 위치, 사진 메타데이터를 저장한다.
- Supabase Storage는 사진 원본과 썸네일을 저장한다.
- PostgREST와 RLS는 사용자별 데이터 접근을 제어한다.

### Google OAuth

- Google OAuth는 로그인 수단으로만 사용한다.
- Google 계정의 비밀번호를 MyTravelDex가 직접 수집하지 않는다.
- 로그인 취소·실패 시 사용자가 재시도할 수 있는 상태를 제공한다.

### Google Maps

- Google Maps는 지도 표시, 위치 선택, 장소 검색, 좌표·주소 보완에 사용한다.
- MVP에서는 Routes, Navigation, Street View를 사용하지 않는다.
- 지도 API가 실패해도 사용자가 좌표를 수동 입력하거나 나중에 재시도할 수 있어야 한다.

## 10. 초기 설정 실패에 대한 사용자 경험

| 상황 | 사용자 경험 |
|---|---|
| Google 로그인 취소 | 로그인 화면에 머물고 재시도 버튼을 제공한다. |
| OAuth 설정 오류 | 원문 오류를 직접 노출하지 않고 로그인 재시도 안내를 제공한다. |
| 사진 권한 거부 | 권한 설정 방법과 수동 기록 방법을 안내한다. |
| 위치 권한 거부 | 사진·기록 등록은 허용하고 지도에서 수동 위치 선택을 제공한다. |
| Maps API 실패 | 지도 오류 상태와 재시도 버튼을 표시한다. |
| Storage 업로드 실패 | 기록 저장을 완료하지 않고 업로드 재시도를 제공한다. |
| 네트워크 오류 | 입력 내용을 유지하고 연결 복구 후 다시 시도하게 한다. |

## 11. 문서 변경 정책

요구사항이 변경되면 `REQUIREMENT.md`를 기준으로 `PRD.md`, `TRD.md`, `AGENTS.md`, `.env.example`의 영향을 함께 검토한다. 사용자 흐름과 MVP 수용 기준이 바뀌었는데 기술 명세나 테스트 범위가 갱신되지 않은 상태에서는 구현을 진행하지 않는다.
